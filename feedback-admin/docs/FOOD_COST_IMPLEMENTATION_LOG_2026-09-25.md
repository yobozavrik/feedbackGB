## Проверка скользящего окна

- До синка окно Europe/Kyiv 22–24.09 имело 52/78 завершённых пар дата×магазин. UI корректно скрывал общие проценты как неполные.
- `node scripts/sync-poster-foodcost-sales-recent.mjs --dry-run` показал 78 пар и отсутствие записей.
- Разрешённый синк `--write`: 78/78 обработано, 37 изменённых и 41 неизменная пара. Порядок: 24, 23, 22.09. Все суммы сохранены в minor units.
- Readback `check-foodcost-recent-network.mjs`: 26 текущих Poster-точек совпали с `v_stores`, окно complete 78/78, missing=0. Оплачено 223 760 905 minor, товарная прибыль 136 287 322 minor, два показателя 39,0924% / 38,6965%.
- Прямая повторная проверка Poster `--verify` для 24.09×точки 1, 13 и 26: по каждой 0 несовпавших строк и 0 разницы денежных полей. Это выборка, а не проверка всех 78 пар.

## Следующий ограниченный блок: категории

- `loadFoodcostSalesPeriod` читает только 1–3 даты и ограниченный список точек. Для каждой пары берёт последнюю завершённую версию, сверяет непрерывность строк, количество и суммы фактов с заголовком run. Неполнота хотя бы одной пары делает все показатели категории/продукта `null`.
- `loadFoodcostRecentBreakdown` повторно сверяет текущие ID точек Poster с `v_stores` и применяет это правило ко всему окну. Read-only CLI: 26 категорий, 269 проданных продуктов, суммы категорий и продуктов равны сети.
- В исторических строках продаж `category_name_snapshot` фактически пуст у всех 26 категорий. Прямой read-only вызов Poster `menu.getCategories` вернул 29 категорий и покрыл ID всех 26 проданных категорий. Для отображения используем **текущие** названия каталога, не выдавая их за исторические. При сбое каталога числовые ID и предупреждение остаются, суммы не меняются.
- Новый защищённый `GET /api/admin/technologist/food-cost/categories/recent-network` — `super_admin`, `no-store`, без сырых фактов и токенов. На `/admin/technologist/food-cost?tab=categories` отображаются категории, количество реально проданных продуктов, оплаченная сумма и обе методики. Ссылка ведёт в существующий каталог; это не утверждение, что число проданных продуктов равно общему числу карточек каталога.
- Авторизованный локальный browser smoke-test: вкладка, светлая/тёмная тема, 390/930/1440 px, переход «Пельмені» → `/admin/technologist/products/category/6` (15 карточек в каталоге), возврат к обзору с 78/78 и пилотом продукта 121.
- После финальной защиты от пустого каталога Poster полный suite: **57 файлов, 428/428 тестов**. `npm.cmd run typecheck` и `npm.cmd run build` на окончательном коде прошли (у build остались предупреждения в ранее существующих absences/schedules). Локальный dev-сервер после build восстановлен на 3210.

## Границы доказательства

- Крон есть в Preview-ветке, не в Production. Его первый запуск и наличие `CRON_SECRET` в Vercel Production не подтверждены.
- Историческое членство магазинов для 7/14/30 дней не доказано; оно не подменяется текущим составом сети.
- Новая вкладка считает две методики из полей продаж Poster, **не** из закупочных накладных; показатели не называются бухгалтерской себестоимостью.
- История продукта, матрица, тепловая карта, Excel и нагрузочная проверка API ещё не завершены. Не маркировать весь план выполненным.

## Продолжение: вкладка «Позиції»

- Добавлен `GET /api/admin/technologist/food-cost/products/recent-network`: только `super_admin`, `no-store`, проверка параметров, серверные поиск/фильтр/сортировка/пагинация (25 строк по умолчанию, максимум 50). Агрегат фильтра пересчитывается из денежных сумм всех отфильтрованных продуктов до пагинации. При неполном покрытии все продуктовые показатели остаются `null`.
- `product_id` — идентификатор группировки. Продажи модификаций суммируются в одном продукте; исторические расхождения названия/категории отмечаются. Для страницы выдачи дополнительно проверяется наличие ID в текущем `v_products`; исчезнувшая карточка остаётся в продажах, но не получает битую ссылку на каталог.
- Во вкладке `/admin/technologist/food-cost?tab=products` показаны оплаченная сумма и две раздельные методики. Количество и цена за единицу сознательно не выведены: единицы и методика их вычисления ещё не подтверждены. Названия продуктов — из снимка продаж Poster, а не замена исторического имени текущим каталогом.
- Read-only диагностический скрипт на окне 22–24.09: 26 категорий, 269 проданных продуктов, суммы категорий и продуктов равны сети; в этой выборке 0 конфликтов имён/категорий/единиц и 0 продуктов вне текущего каталога. Это доказательство только для проверенного окна, не постоянный инвариант.
- Адресные тесты API/пагинации/фильтров/исторического ID и проверка типов прошли. Полный прогон: **59 файлов, 440/440 тестов**. Production-сборка прошла после остановки локального dev-сервера и очистки только сгенерированного `.next`: одновременная сборка и dev-сервер на одном каталоге первоначально вызвали `PageNotFoundError` для существующего HR-маршрута. После чистого перезапуска `/login` загружается. Известные предупреждения линтера остались в absences/schedules.
- Без сессии прямой GET нового API вернул 401 `unauthenticated`; unit-тест проверил 403 на уровне маршрута. После входа администратором авторизованный Playwright E2E локально прошёл: 269 позиций и сумма 2 237 609,05 ₴ совпали с read-only readback; фильтр категории «ПИРІЖЕЧКИ» дал 6 позиций и 45 176,93 ₴; возврат к сети восстановил 269; вторая страница показала следующие 25 строк без изменения общего итога; поиск «Пельмені зі свинини» дал 3 позиции и 289 695,61 ₴; клик по #121 открыл существующую карточку продукта с вкладками залишків/техкарты. Скриншоты 1440×900 в светлой и тёмной теме и 390×844 визуально просмотрены, критичных дефектов вкладки не обнаружено. Консоль содержала только 404 на `favicon.ico`, не ошибку приложения. Это проверка локального контура, не Preview/Production.

## Следующий ограниченный блок: фудкост в карточке продукта

- Добавлена вкладка «Фудкост» в существующую карточку каталога, без изменения фото, залишків, характеристик и техкарты. Глубокая ссылка из «Позиції» ведёт на `?tab=foodcost`; выбранная вкладка сохраняется в URL.
- Тот же read model полного окна 22–24.09 группирует факт продаж по продукту, дню и магазину. Суммы оплаченного, `product_profit` и `product_profit_netto` в обеих разбивках должны сходиться с продуктовым итогом; иначе маршрут не показывает противоречивые цифры. Продукт без продаж — `Н/Д`/«Не продавався», не нулевой процент.
- Новый `GET /api/admin/technologist/products/[id]/food-cost` доступен только `super_admin`, `no-store`, валидирует ID и возвращает только агрегаты. Имена магазинов читаются из текущего `v_stores` после сверки набора ID с Poster; это **текущие названия**, не исторические снимки названий.
- Локальный авторизованный E2E: переход из списка открыл `item/121?tab=foodcost`, итог 96 857,43 ₴ и 41,06 %/41,06 % совпал с строкой списка; три даты и 26 магазинов показаны, 78/78 снимков. Скриншоты 1440×900 в обеих темах и 390×844 просмотрены. Страница не содержит ошибки приложения; 404 `favicon.ico` был и до этой вкладки.
- **Граница:** пока это блок фактических продаж, а не весь шаг 15 плана. Прайс по магазинам, норматив техкарты и закупочные накладные для всех продуктов ещё не перенесены в эту вкладку. Текущая себестоимость POS остаётся в боковой карточке и не смешивается с историческим фактом.
