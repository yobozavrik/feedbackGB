# Галерея фото-звітів: план впровадження

## Мета

Адмін має бачити не лише суму фото за магазином, а кожну окрему відправку за день: хто надіслав, коли, скільки фото і самі зображення.

## Правило даних

Кожна кнопка «Надіслати» продавчині створює один окремий рядок `feedback` з `category = photo_report`.

| Сценарій | Дані в БД | Відображення |
|---|---|---|
| 1 відправка, 15 фото | 1 рядок, 15 посилань | `Звітів: 1`, `Фото: 15` |
| 3 відправки за день | 3 рядки | `Звітів: 3`, `Фото:` сума всіх трьох |
| 3 продавчині одного магазину | 3+ рядки з різними `user_id` | У кожному звіті видно автора і час |

## Кроки

1. Зберігати всі фото одного звіту в `photo_urls`, а перше — у `photo_url` для сумісності. **Готово.**
2. Агрегувати за `store_id` і календарним днем `Europe/Kyiv`; не змішувати UTC-дату з операційним днем. **Готово.**
3. У таблиці «Фото звіт» показувати `Звітів`, суму `Фото`, список продавчинь та останню відправку. **Готово.**
4. За кнопкою «Відкрити фото» запитувати дані одного магазину і однієї дати, створювати тимчасові Storage URL на 10 хвилин, групувати у блоки «Звіт 1…N». **Готово.**
5. У загальній стрічці при відкритті конкретної заявки показувати всі її фото у `Image.PreviewGroup`, а не лише перше. **Готово.**
6. Перевірити E2E двома тестовими продавчинями: три відправки в один день, різна кількість фото, інший магазин без звіту. **Потрібні тестові PIN та preview Ready.**

## Безпека

- Доступ до обох API галерей — лише `admin` / `super_admin`.
- У базі зберігається шлях `sb:`; у браузер передається лише короткочасна підписана URL.
- API не приймає шлях до Storage від клієнта, а шукає рядок за `feedback.id` або за довіреним `store_id` + датою.
- Фото, PIN, cookie і токени не записуються в журнали.

## Acceptance-тест

1. Продавчиня A надсилає 3 фото о 09:00, 5 фото о 13:00.
2. Продавчиня B того ж магазину надсилає 4 фото о 17:00.
3. У «Фото звіт» є один магазин: `Звітів: 3`, `Фото: 12`, обидва продавці.
4. Галерея містить три окремі блоки з правильним часом, автором і кількістю.
5. Відкриття конкретної записи в загальній стрічці показує лише фото цієї відправки.
6. Продавчиня або неавторизований користувач отримує `403` від обох API галерей.
