# Макеты: Магазини → Аналітика

Дата29.09.2026. Основа: текущие stores-tabs.tsx и lib/admin/theme.ts. Это проектируемые экраны, не реализованные production pages. Цифры в макете демонстрационные.

## Общий каркас

Существующий sidebar/56px header сохраняются. Heading «Магазини», верхние Tabs «Магазини / Звіти / Аналітика». Внутри последней — локальная навигация7 views, общий фильтр и качество; на узких экранах навигация через select, не семь сжатых кнопок.

Inter14, containers12px, controls36px, нейтральные tables/cards, pink только акцент активной вкладки и основного series. Green/red у знакаΔ — направление; warning у неполного источника. Dark без белых карточек, те же семантические цветовые токены. Не вводить новый шрифт или новый дизайн-system.

## Экран1: Огляд

```text
Магазини                             Магазини | Звіти | [Аналітика]
[30 днів] [від—до] [Вся мережа] [попередній період] [день]
Огляд | Магазини | Категорії | Товари | Проникнення | Порівняння | Якість
Джерело/перевірено/asOf/повнота
[Виручка] [Зміна₴/%] [Чеки*] [Середній чек*]
[Тренд поточного та попереднього періоду 2/3] [Внесок магазинів1/3]
```

*Если receipts не приняты, видимое «Чекові дані ще не підтверджені». Line points→дата, bars→магазин, category→категория. Никакого «хорошо» исключительно по росту выручки.


Карточка магазина — аналитический экран, не замена каталога магазинов. Scope остаётся виден; benchmark «сеть» включает магазин, peer benchmark без него подписывается отдельно.

## Экран3: Категорії

```text
[всі категорії] [метрика: частка виручки]
Тренд вибраної категорії | Рейтинг категорій
Магазин × Категорія — квадратні heatmap cells
Категорія / Виручка / Частка% / Δ₴ / Δчастки п.п. / Охоплення
```

Одинаковая шкала heatmap и названный denominator. Клик cell → магазин+категория в «Товари».

## Экран4: Товари / карточка позиции

```text
[пошук товару] [категорія] [одиниці]
Товар / кг або шт / виручка / частка / Δ / охоплення / проникнення*
Пельмені зі свинини
[Виручка] [Продано кг] [Ціна продажу₴/кг] [Δ]
[Тренд виручки] [Магазини: обсяг/виручка/частка]
[Деталі технолога] [До списку товарів]
```

Не складывать unit bases, прайс и effective selling price показывать раздельно. Текущая техкарта не историческая себестоимость.

## Экран5: Проникнення

```text
[У чеки* | Охоплення магазинів продажами] [Категорії | Товари]
Магазин × Категорія/товар: % в квадратних комірках
Частка чеків: numerator/denominator / дата / магазини
[Тренд вибраної категорії] [Рейтинг магазинів]
```

Чековый mode disabled с объяснением, если источник не готов. Hover/focus/tap раскрывают полные числа. «—» с hatch=missing; 0%=проверенный ноль; категории overlap, поэтому donut здесь не используется.

## Экран6: Порівняння

```text
[ПеріодА] [ПеріодБ] [та сама вибрана мережа]
[А виручка] [Б виручка] [Δ₴] [Δ%]
[Waterfall внесків] [тренди / день або тиждень]
Магазин | А | Б | Δ₴ | Δ% | ПовнотаА/Б
Категорія/товар → деталізація внеску
```

Показать итог и revenue/day отдельно. Никаких LFL без интервалов исторической применимости.

## Экран7: Якість даних

```text
Продажі: verified/expected    Чеки: verified/expected
Магазин × День: complete / verified empty / missing / N/A / provisional
Магазин | пропущені дати | last verified | run/error | стан
```

Экран не запускает записи автоматически. Coverage относится отдельно к sales и receipts. Полная текущая выбранная сеть не утверждает правильность исторической популяции.

## Поведение макета

В чат показан один интерактивный проект структуры с переключением всех7 экранов, выбором scope и открытием demo product. Он не ходит в Poster/Supabase. Выбор store/category меняет локальный mock focus; заданные demo values не являются расчётом при переключении произвольных дат.

При реализации фильтры должны пересчитывать реальные данные единым pipeline; невозможность источника отражается честным unavailable. Макет не проходит business-data acceptance; UI/E2E и parity checks выполняются на настоящей реализации по отдельному плану.
