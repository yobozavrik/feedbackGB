# Дозагрузка чеков Poster по дням — журнал проверки

Контур: общая Supabase, схема `feedbackgb`. История загружается **по одному завершённому дню**, без параллельных публикаций. Каждый день: отсутствие принятого запуска → `--prepare-only` (двойное чтение Poster) → `--publish` → независимые SQL-сверки. Сбой любого шага останавливает переход к следующему дню. Сырые чеки и данные клиентов в журнал не копируются.

На 26–27.09 проверены количество и ключевые поля оригинала (ID чека, магазин, клиент, закрытие, количество строк), **не** полное сравнение каждого поля проекции. Публикация архивирует исходные ответы Poster целиком; аналитические выводы по денежным полям до отдельной проверки их единиц измерения делать нельзя.

Длинная история с 01.01.2026 и ночной cron на момент этой записи **ещё не завершены**. Не считать подготовленный день опубликованным без `accepted` и readback. Для повторного запуска одного дня сначала сверить существующий `run_id`: из-за неизменяемого архива новый снимок того же дня создаст новую версию, а не перезапишет старую.
