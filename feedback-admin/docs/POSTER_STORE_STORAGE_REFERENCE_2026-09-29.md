## Правила использования

- `feedbackgb.v_stores.id` и `categories.spots.spot_id` совпадают с Poster `spot_id` для всех 26 текущих точек. `storage_id` — другой идентификатор; например, **Клуб: магазин 18, склад 52**.
- Для текущего мапинга используйте `access.getSpots[].storages[].storage_id`; не связывайте магазин и склад по похожему названию и не полагайтесь только на `categories.storages.spot_id`: так потеряется Рута.
- Для магазина с нулём или несколькими складами связь должна считаться неподтверждённой. В этом снимке таких случаев **0**; ID магазинов и ID складов уникальны внутри выбранных пар.
- Это **текущий** снимок, не история интервалов действия связей. Нельзя автоматически применять его к накладным, остаткам или продажам прошлых дат без проверки исторического мапинга.
- Склады без связи с магазином (цеха и прочие склады) в таблицу не включены. Склад 59 — исключение: название магазинное, поле БД пустое, но прямая связь Poster подтверждена.

## Повторная проверка

Из `feedback-admin` запустить `node scripts/verify-poster-store-storage-map.mjs`. Скрипт читает `POSTER_TOKEN` из окружения проекта, не печатает токен, URL запроса или прочие поля Poster, не пишет в БД. Сверить новый результат с таблицей выше и `feedbackgb.v_stores` / `categories.storages`; при изменении состава создать новый датированный снимок, не переписывать этот как историческую истину.

Проверка на момент создания: Poster — 26/26 точек с одним складом; `feedbackgb.v_stores` — 26 активных магазинов; `categories.storages.spot_id` — 25 однозначных связей, 1 отсутствующая (`Рута`), 0 неоднозначных.
