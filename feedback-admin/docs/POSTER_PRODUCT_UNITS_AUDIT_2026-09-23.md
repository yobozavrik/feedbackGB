# Одиниці виміру продуктів Poster — перевірка 23.09.2026

## Джерела та покриття

Read-only команда: `cd feedback-admin; node scripts/audit-poster-units.mjs`. На дату перевірки успішно прочитано 372 картки `feedbackgb.v_products`, 359 продуктів Poster, 330 напівфабрикатів, 26 складів. Усі 359 `menu.getProduct` і 330 `menu.getPrepack` відповіли; помилок не було. Скрипт не друкує URL запитів чи токен.

| Джерело | Фактичні коди |
| --- | --- |
| Каталог карток | `kg`: 356; без одиниці: 16 |
| Рецепти продуктів, рядки | `g`: 1826; `ml`: 34; `p`: 716 |
| Рецепти напівфабрикатів, рядки | `g`: 1661; `ml`: 138; `p`: 4 |
| Склади, рядки 26 магазинів | `kg`: 13546; `l`: 416; `p`: 11024 |

Відображення: `kg → кг`, `g → г`, `l → л`, `ml → мл`, `p → шт`. Приклади рядків `p` у живому Poster: паперовий пакет, етикетка, лоток — по 1–2 одиниці. Відображення не перераховує значення: `0.5 kg` лишається 0.5 кг (у таблиці з українським форматуванням — `0,5 кг`), а не `500 г`; складські нулі й від’ємні кількості не змінюються.

У 16 продуктів типу `3` одиниця в поточному каталозі не задана. Частина має поштучні складські рядки, частина — не має складського рядка взагалі. Висновок для загальної картки та форми продавця: **не вважати порожню одиницю автоматично штуками**. У картці це `—`, у виборі продавця — «Одиницю не вказано»; якщо складський рядок існує, саме залишок показує його фактичну одиницю `шт`.

## Додаткова перевірка після повідомлення про хибне `шт`

Повторна read-only перевірка 23.09.2026: у 170 продуктів `menu.getProducts.unit = kg`, але відповідний `ingredient_id` у `storage.getStorageLeftovers` має `ingredient_unit = p`. Складський endpoint повертає однаковий код для одного ingredient_id на всіх перевірених 26 складах: змішаних `kg`/`p` для однієї позиції — 0. Отже, поле одиниці товару і поле одиниці складського обліку не можна вважати взаємозамінними. Техкарта має власний `structure_unit`, який треба показувати по рядку.

Цей замір сам по собі **не доводить**, що конкретне відображення `шт` правильне для бізнес-контексту: потрібні ID/назва продукту та вкладка, де очікується інша одиниця. Без цього масова заміна `p → кг` пошкодила б дійсно поштучні залишки; конверсії кількостей не виконувалися. Для повторення діагностики скрипт тепер виводить кількість розбіжностей каталогу і складу, приклади та перевірку змішаних одиниць між магазинами.
