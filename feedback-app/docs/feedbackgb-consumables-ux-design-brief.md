# ТЗ: UX/UI для заказа расходных материалов

## 1. Цель

Спроектировать мобильный сценарий заказа расходных материалов для продавцов в Telegram Mini App FeedbackGB.

Пользователь выбирает позиции из каталога склада, меняет количество, отправляет заявку. Сервер FeedbackGB передает ее напрямую в складскую CRM. Заявки разных пользователей одной локации могут объединяться в одну открытую CRM-заявку.

Нужен не редизайн одной формы, а ясный быстрый сценарий работы на телефоне одной рукой.

## 2. Контекст и аудитория

- Пользователь: продавец магазина, в большинстве случаев без обучения работе в CRM.
- Устройство: смартфон, Telegram WebView, рабочая ширина 320–430 px.
- Сценарий: сотрудник быстро добавляет несколько знакомых позиций во время смены.
- Каталог и единицы измерения приходят из складской CRM; цены в Mini App не показываются.
- Магазин определяется по авторизации. Пользователь не выбирает локацию вручную.

## 3. Главная UX-задача

Пользователь должен пройти путь без потери контекста:

1. Найти или увидеть товар.
2. Добавить его и изменить количество прямо там, где он найден.
3. Понять, что уже в корзине.
4. Открыть короткую проверку корзины.
5. Добавить комментарий при необходимости.
6. Отправить заявку и получить подтверждение, что она ушла на склад.

Не использовать один длинный экран, на котором одновременно каталог, длинная корзина, комментарий и отправка: на телефоне это заставляет постоянно скроллить между действиями.

## 4. Обязательная информационная архитектура

Нужны два основных экрана, а не одна перегруженная форма.

### Экран A — каталог и набор корзины

Это основной рабочий экран.

- Компактный заголовок: «Розхідні матеріали».
- Поле поиска по названию товара.
- Список товарных строк: название, единица измерения, опционально категория.
- Не выбранный товар: одна ясная кнопка «Додати».
- Выбранный товар: управление количеством прямо в строке `− / число / +`.
- Уменьшение количества до нуля убирает позицию из корзины.
- Внизу всегда закреплена CTA-кнопка: `Кошик · N поз. · M од.`. Она открывает экран B.
- При пустой корзине CTA заблокирована и явно объясняет состояние.

### Экран B — проверка и отправка корзины

Это короткий финальный экран, без каталога.

- Название «Кошик» и счетчик позиций/единиц.
- По каждой позиции: название, единица, `− / число / +`, явная иконка удаления.
- Действие «Продовжити вибір» возвращает в каталог без потери корзины.
- Необязательный комментарий для кладовщика.
- Внизу закреплена кнопка «Відправити заявку».
- Под кнопкой спокойное пояснение: «Заявка потрапить прямо на склад».

## 5. Экраны, которые команда должна отрисовать

Каждый экран — mobile high-fidelity, 390 px ширина. Нужны light theme и кликабельный прототип основного потока.

1. Экран A: пустая корзина, каталог загружен.
2. Экран A: поиск введен, показаны результаты.
3. Экран A: 2–3 товара уже добавлены; в их строках видны quantity steppers и активная кнопка корзины.
4. Экран A: пустой результат поиска.
5. Экран A: ошибка загрузки каталога с действием «Спробувати ще раз».
6. Экран B: корзина с несколькими позициями.
7. Экран B: удаление позиции — либо undo-snackbar, либо диалог подтверждения. Выбрать один вариант и показать его.
8. Экран B: пользователь уменьшает последнюю единицу товара до нуля.
9. Экран B: кнопка отправки в состоянии loading.
10. Экран успеха: заявка принята складом, CTA «Створити ще одну заявку» и переход к истории заявок.
11. Экран ошибки отправки: заявка не принята складом, позиции сохранены в корзине, есть «Спробувати ще раз» и возврат к редактированию.
12. Экран «Мої заявки» / история: карточки заявок и статусы.
13. Деталь одной ранее отправленной заявки: позиции, количества, комментарий, временная шкала статуса.

## 6. Статусы заявок

В макетах заложить следующие пользовательские статусы и один цвет/иконку на каждый:

| CRM-статус | Текст для продавца | Смысл |
|---|---|---|
| `submitted` | «Заявка прийнята» | поступила на склад, ожидает обработки |
| `picking` | «Збирається на складі» | кладовщик начал подбор |
| `ready` | «Готова до видачі» | можно ожидать передачу/доставку |
| `shipped` | «Відправлена» | склад передал материалы |
| `completed` | «Отримана» | локация получила материалы |
| `cancelled` | «Скасована» | заявка не будет выполнена; обязательна причина |
| `partially_fulfilled` | «Зібрана частково» | обязательны недостающие позиции или комментарий |

Важно: сейчас API FeedbackGB гарантированно создаёт заявку в CRM, но API чтения этих статусов еще не реализован. Дизайн не должен считать, что все статусы уже доступны; это отдельная задача для разработки после утверждения макетов.

## 7. Требования к взаимодействию

- Минимальный интерактивный размер — 44×44 px.
- Количество меняется одним нажатием; не использовать ввод числа с клавиатуры как основной путь.
- Удаление должно быть явным и доступным, но не стоять рядом с главной кнопкой отправки.
- Корзина сохраняется при возврате из экрана B в экран A.
- Нельзя терять заполненную корзину при временной ошибке сети или CRM.
- Не использовать цены, остатки, поставщиков, складские ID и технические статусы в интерфейсе продавца.
- Не использовать модальные окна для каждого добавления товара.
- Учитывать safe area Telegram/iOS для нижней закрепленной панели.

## 8. Визуальное направление

Не копировать текущую длинную форму. Нужен спокойный рабочий интерфейс, а не маркетинговый лендинг.

- Сохранить существующую идентичность FeedbackGB: светлый фон, белые поверхности, синий primary-action, темный текст.
- Одна главная CTA на экран.
- Карточки использовать только для товарных строк и важных состояний; не оборачивать каждый текст в отдельную карточку.
- Показывать четкую иерархию: название товара → единица → действие.
- Иконки — единый line icon set, не emoji.
- Высокий контраст текста и состояний; цвет не единственный носитель смысла.

## 9. Что не входит в эту задачу

- Изменение PIN-авторизации и определения магазина.
- Изменение других категорий FeedbackGB.
- HR-раздел.
- Изменение бизнес-логики объединения заявок в CRM.
- Показ цены, остатков или поставщиков.

## 10. Что команда должна передать

1. Figma-файл с компонентами и стилями.
2. Три разных UX-варианта для экранов A и B до выбора одного направления.
3. После выбора — полный набор экранов из раздела 5.
4. Кликабельный прототип: поиск → добавить → изменить количество → корзина → комментарий → отправка → успех.
5. Короткая спецификация компонентов: размеры touch targets, состояния кнопок, steppers, ошибки, skeleton/loading, empty states, status chips.

## 11. Критерии приемки дизайна

- Новый сотрудник без инструкции может добавить два разных товара, поменять количество и отправить заявку менее чем за минуту.
- В каталоге пользователь всегда понимает, какие товары уже добавлены и в каком количестве.
- В корзине можно изменить количество и удалить позицию без возврата в каталог.
- Никакой важный CTA не скрыт за прокруткой.
- Все обязательные, пустые, loading, success и error состояния показаны в Figma.
- Статусы представлены понятным языком, а не кодами CRM.
